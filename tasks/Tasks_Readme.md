# Tasks Application Explanation

This document outlines the purpose and operation of the core files within the `tasks` application. This application is designed to manage projects and tasks, serving as a core functional component (likely tenant-specific) of the system.

## Files Overview

The `tasks` application consists of the following key files:

* `models.py`
* `serializers.py`
* `views.py`
* `admin.py`
* `core/urls.py`

### `models.py` (The Data Layer)

* **Purpose:** Defines the database structure for managing work items.
* **Operation:**
  * **`Project`**: Represents a container for tasks. It includes a short `key` (which is indexed for performance), a `name`, and a `description`.
  * **`Task`**: Represents an individual unit of work. It has a Foreign Key relationship to `Project` (`related_name="tasks"`), a `name`, `description`, and a boolean `is_done` status.
  * **Inheritance:** Both models inherit from `TimeStampedModel` (imported from `core.models`), ensuring `created_at` and `updated_at` timestamps are automatically maintained.
  * **String Representation:**
    * `Project`: Returns a string like "Project Name (KEY)".
    * `Task`: Returns a string like "[KEY-ID] Task Name".

### `serializers.py` (The Translator)

* **Purpose:** Handles the conversion between `Project`/`Task` model instances and JSON format for API communication.
* **Operation:**
  * **`ProjectSerializer`**: Standard serialization exposing fields like `id`, `key`, `name`, and timestamps.
  * **`TaskSerializer`**:
    * **Nested Representation:** Defines `project` as a `ProjectSerializer(read_only=True)`. This means when fetching a task, the full details of the associated project are embedded in the response.
    * **Write Operations:** Defines `project_id` as a `PrimaryKeyRelatedField(write_only=True)`. This allows API clients to create or update a task by sending just the project's ID, while still receiving the full project object in the response.

### `views.py` (The Logic/Interface Layer)

* **Purpose:** Provides the API endpoints for interacting with projects and tasks.
* **Operation:**
  * **`ProjectViewSet`**: Provides standard CRUD (Create, Read, Update, Delete) operations for Projects.
  * **`TaskViewSet`**: Provides standard CRUD operations for Tasks.
    * **Optimization:** The queryset uses `.select_related("project")`. This is a crucial optimization that performs a SQL JOIN to fetch the associated project data in the same database query as the task. This prevents the "N+1 query problem" caused by the nested serializer accessing project attributes.

### `admin.py` (The Management Layer)

* **Purpose:** Configures the Django Admin interface for internal management of tasks and projects.
* **Operation:**
  * **`ProjectAdmin`**: Customizes the list view to show the project key and name.
  * **`TaskAdmin`**:
    * **Display:** Shows task name, associated project, completion status, and timestamps.
    * **Filters:** Adds sidebar filters for `project` and `is_done` status.
    * **Search:** Enables a search bar to find tasks by name or description.

### `core/urls.py` (The URL Configuration)

* **Purpose:** Defines the URL patterns for the tenant schemas, making the tasks application's API endpoints accessible.
* **Operation:**
  * **`urlpatterns`**:
    * **`index_view`**: The root URL (`/`) displays a JSON response with project and task counts.
    * **`api/`**: The `/api/` prefix includes the router's URLs, which are generated by the `DefaultRouter` in `core/urls.py`. This includes the `ProjectViewSet` and `TaskViewSet` endpoints.
    * **`admin/`**: The `/admin/` URL includes the Django admin site for managing tasks and projects.
    * **`blog/`**: The `/blog/` prefix includes the router's URLs for the blog application.
    * **`tasks/`**: The `/tasks/` prefix includes the router's URLs for the tasks application.

## Data Flow

1. **Request:** An API client sends a request (e.g., `GET /api/tasks/`).
2. **View:** The `TaskViewSet` executes a query. Thanks to `select_related`, it fetches tasks and their parent projects in a single SQL command.
3. **Serializer:** The `TaskSerializer` processes the data. It maps the task fields and uses the nested `ProjectSerializer` to format the project data.
4. **Response:** The API returns a JSON response containing the task information with the embedded project details.
5. **Admin:** Alternatively, an administrator can log in to the Django Admin panel to view, filter, and search these records using the configurations in `admin.py`.
